## Build & Verification Rules

- **Single gate**: `cd Q:/repos/fsion && pwsh -NoProfile -File eng/gate.ps1` builds Release (both TFMs), publishes NativeAOT `fsion` for `net10.0` and `net11.0` into `artifacts/publish/fsion/<tfm>/`, runs `dotnet test` per TFM, and checks LF hygiene. Tests resolve the published `fsion` and `src/fsiond/bin/Release/<tfm>/fsiond.exe`, so publish before testing.
- **100% F# (`net10.0;net11.0`)**: Keep all product and test projects in F# under `Directory.Build.props` (`TreatWarningsAsErrors=true`, `Deterministic=true`).
- **Two shipping binaries**:
  - `fsion`: NativeAOT (`PublishAot=true`) thin client with zero AOT/trim warnings and zero `printf` reflection traps (`MakeGenericMethod`).
  - `fsiond`: CoreCLR reactor hosting `FSharp.Compiler.Service` over private local IPC (Windows Named Pipe on Windows; Unix Domain Socket on macOS/Linux).
- **Windows AOT publish toolchain**: ILCompiler 10.0.15's `findvcvarsall.bat` captures VS18 `vcvarsall.bat` stderr; a bare `vswhere.exe` failure (`VS Installer` dir not on `PATH`) corrupts the captured `link.exe` path. `eng/gate.ps1` prepends `${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer` when `vswhere.exe` exists; keep that when scripting publishes elsewhere.
- **Zero temporary `.dll` writes on the hot path**: Evaluate scripts in memory (`Reflection.Emit` / `FsiEvaluationSession` with `--optimize- --multiemit-`) so Windows Defender never scans per-run binaries.
- **Process & file hygiene in tests**:
  - Never kill processes globally by name (`taskkill /IM dotnet.exe`, `pkill -f dotnet`); isolate test daemon endpoints/pipes per test run and shut down only the test's own daemon instance.
  - Keep all tracked text files LF-terminated (`git ls-files --eol` -> `i/lf`).
  - On Windows Git Bash, never run `find /` (it crawls entire drives and hangs); query `dotnet nuget locals global-packages -l` when inspecting the NuGet cache.
- **Comments**: Default to zero comments; keep short inline notes only for non-obvious platform/IPC/AOT hazards.
- **Packaging**: `pwsh -NoProfile -File eng/package.ps1 [-Framework net10.0|net11.0] [-Runtime <rid>]` publishes the host-RID bundle into `artifacts/package/fsion-<rid>-<tfm>/` and runs it from a fresh temp directory (the smoke test intentionally does not set `FSIOND_PATH`, so the packaged `fsion` must find the packaged `fsiond` next to itself). NativeAOT cannot cross-compile to another OS: `-Runtime` must match the host OS, and the 3-OS CI matrix runs one bundle per OS. The script also carries the VS Installer PATH fix and must keep it.
- **Benchmark**: run `python bench/run-bench.py` separately from builds and tests. Goal 0006 writes `docs/evidence/0006-benchmark-{report.md,results.json}`; keep the 0005 records unchanged. Keep the repo-local `bench/.work/` carrier: `%TEMP%` on this host makes `bun` ~2x slower, biasing the comparison.

## Windows IPC & Process Hazards

- `fsion` spawns `fsiond` on Windows via Win32 `CreateProcessW` with `bInheritHandles=false` and `CREATE_NO_WINDOW | DETACHED_PROCESS` (`Ipc.spawnDetached` in `src/Fsion.Protocol/Ipc.fs`, shared with the drain-and-respawn path). `Process.Start` sets `bInheritHandles=TRUE`, so a long-lived `fsiond` would inherit the caller's `stdout`/`stderr` pipe write ends and any redirected `ReadToEnd`/`capture_output` would block forever after `fsion` exits. Do not revert the Windows path to `Process.Start`.
- Stateless `Execute` turns consume one collectible session, dispose statics and release transient resources before replying. Same-cwd, same-environment turns can share a `ProcessStateGate` epoch. Different epochs serialize, and the final turn restores the daemon cwd before replying.
- Windows Named Pipe names (`--pipe` / `FSION_PIPE`) must be single-segment names without `\` or `/`; `resolveEndpoint` rejects path separators in `src/fsion/Program.fs` and `validateEndpointName` in `src/Fsion.Protocol/Ipc.fs` enforces it at connect/listen time.

## Daemon Pool & Isolation Invariants

- `src/fsiond/Ambient.fs` installs `AsyncLocal`-routed `Console.Out`/`Console.Error`/`Console.In` writers once at daemon startup; runs set their per-run `StringWriter`s in the ambient context. Never `Console.SetOut`/`SetError` a shared session per run.
- `src/fsiond/SessionHost.fs` owns the warm pool (default watermark 4 per retained prelude; client `fsion --pool-size <n>` passes through to the auto-started daemon and its respawn replacement, daemon `fsiond --pool-size <n>` / `FSION_POOL_SIZE` are the direct equivalents, `0` disables warm sessions so every run claims cold), the `ProcessStateGate` cwd/env epochs, `--json` diagnostic collection, and the prelude `exit` shadowing. `fsion --json` emits one `Utf8JsonWriter` document (`exitCode`, `stdout`, `stderr`, `timedOut`, `elapsedMs`, `diagnostics[]`); default mode stays raw stream/exit passthrough.
- `src/fsiond/SessionHost.fs` clears script statics and waits for transient finalizers before a stateless reply. Sweep through the oldest generation the script could have reached, escalating on racing collections and escalating to Gen-2 whenever an exact newly opened regular disk file handle (`NtQueryInformationProcess(ProcessHandleInformation)` + `(HandleValue, dwVolumeSerialNumber, FileIndex)` via `GetFileInformationByHandle` on Windows, or conservatively whenever any pre-existing regular file handle is not in the exact `(HandleValue, dwVolumeSerialNumber, FileIndex)` runtime baseline captured at startup, builtin warmup, and `AppDomain.CurrentDomain.AssemblyLoad`—or whenever more than one handle targets the same `(dwVolumeSerialNumber, FileIndex)`; `/proc/self/fd` or `/dev/fd` with conservative escalation on unresolved non-stdio FDs on POSIX) survives the Gen-0/Gen-1 sweep, rather than relying on net OS handle counts (`GetProcessHandleCount`) or NT `GrantedAccess`/`PointerCount` fields, which can be masked by unrelated handle closes or cached opens. Defer FCS detach, disposal, and full unload (`GC.Collect(2)`) onto `pendingCleanups`, draining after 500 ms quiet or when 16 sessions are pending. Keep the `Metrics` barrier explicit.
- `ExecuteRequest` carries the client's full environment snapshot. `ProcessStateGate` reconciles changed keys at the next epoch instead of restoring the baseline on every reply. `GetMetrics` is the black-box pool and unload probe; `PoolTarget` is per retained tag and `PoolWarm` is aggregate.

## Goal 0003 — Named Sessions, Cooperative Timeout & Drain-and-Respawn

- `--session <id>` binds a run to a named live session in `SessionHost.fs` (`Dictionary<string, NamedSessionEntry>` under one lock; each entry has its own `SemaphoreSlim(1,1)` gate and its own prelude state). Named turns skip `releaseSession` on normal return, so bindings/values persist; `--reset` disposes synchronously through `releaseSession` while the background TTL sweeper enqueues onto `enqueueCleanup` so quiet-window GC rules apply. The idle TTL is a daemon option (`--session-ttl <minutes>` / `FSION_SESSION_TTL_MINUTES`, default 15 min; sweep interval `max(250, min(5000, ttl/4))` ms). `--no-daemon` cannot be combined with `--session`.
- Every run gets a per-invocation `CancellationTokenSource` in `SessionHost.Execute`. It is exposed to scripts as `fsionFsiState.CancellationToken` and passed to `EvalInteraction(..., cancellationToken = ...)` (FCS 43.13.101 has no token overload on `EvalScript`). FSharp.Core 11's `Async.DefaultCancellationToken` is one process-global `CancellationTokenSource`, so it is never swapped or cancelled per run; cooperative scripts pass the exposed token explicitly (`Async.RunSynchronously(Async.Sleep 10000, cancellationToken = fsionFsiState.CancellationToken)`).
- `SessionHost.Execute` acquires the session (cold claim, or a named entry's first claim) before arming the per-evaluation `--timeout` timer, which starts immediately before `evaluate`; a busy named session's gate wait is bounded by the remaining deadline and times out in place (`124`/`TimedOut`/`Wedged = false`), and `creationGate.Wait(disconnectToken)`/gate waits abort a disconnected acquisition in place. It evaluates on a dedicated `LongRunning` task and waits 1500 ms past cancellation for the worker. A cooperative return reports exit `124` + `TimedOut = true` (`--json` `timedOut`) with `fsion: script timed out after <ms> ms` on stderr and leaves the daemon in place. Only a run that entered evaluation (`evaluationStarted` set before `evaluate`, reset in its `finally`) and still runs after the grace window is wedged: `Server.handleConnection` stops the listener, releases endpoint ownership, schedules a hard `Process.Kill` backstop 1 s after detach, sends the timeout response, and spawns a replacement generation via `Ipc.spawnDetached` (skipped for `--no-daemon`).
- Windows endpoint ownership is a named `Semaphore` (`Local\fsion-endpoint-<name>`, count `1` acquired via `WaitOne` and released inside `Server.stop`), not a `Mutex`, because both `daemon stop`/`restart` and the drain path release ownership from the connection-handler thread before the exiting process finishes tearing down; `WaitOne` timeout means another daemon owns the endpoint. `fsiond` enforces `--timeout` after session acquisition, so the client's `receive.Wait` is only a last-resort net with a `timeoutMs + 30000` ms cushion; it synthesizes the exit-124 timeout result if that client deadline expires before `fsiond` replies; if `fsiond` closes the connection without a frame (`daemon stop` / crash), `NoResponse` still surfaces as exit 1 (`fsiond closed the connection without a response`), so daemon death is never masked as a script timeout.
- Protocol version 3: `ExecuteRequest.SessionId/Reset/TimeoutMs`, `ExecutionResult.TimedOut`, `MetricsInfo.NamedSessions`. Black-box coverage lives in `tests/Fsion.Tests/SessionTests.fs` and `tests/Fsion.Tests/RecoveryTests.fs`.

## Goal 0004 — Agent Prelude & Cached NuGet Directives

- `src/Fsion.Protocol/Prelude.fs` owns the shared `FSION_PRELUDE` / `FSION_CONFIG_DIR` / `FSION_CACHE_DIR` resolution (`configuredPreludePath ()`, `userPreludePath ()`, `userPreludePathForEnvironment`, `cacheDirectory ()`); `src/fsiond/Prelude.fs` owns `Spec` (`Bare | Builtin | File path`) and `Tag` (`Bare | Builtin | File(path, SHA-256)`). On daemon-backed executions without explicit `--prelude`/`FSION_PRELUDE`, `fsion` resolves explicit `FSION_CONFIG_DIR` locally (matching `warmup` including Windows per-drive state, and passing `--builtin-prelude` when auto-starting `fsiond` if no caller-side file resolved) and otherwise leaves `PreludePath = None` so `fsiond` resolves any implicit user `prelude.fsx` from `request.Environment` + startup-cached OS account home (`~/Library/Application Support/fsion/prelude.fsx` on macOS, rooted `XDG_CONFIG_HOME` else `~/.config/fsion/prelude.fsx` on Linux when the resolved base config directory exists—never falling back to `./fsion/prelude.fsx` in `cwd` when missing—and `SpecialFolder.ApplicationData` on Windows, avoiding per-invocation Win32 shell-folder resolution in `fsion`), while `warmup` resolves client-side so `Ping(None, false)` always targets `Spec.Builtin`. Every path is normalized with `Path.GetFullPath` at the spec/tag boundary because `Spec`/`Tag` equality is string equality.
- `SessionHost` retains two recent prelude specs (protecting any pool with active foreground or background `Claimers > 0` from eviction, re-verifying pool retention atomically when incrementing `Claimers` in `replenish`, prioritizing pools with active `WarmupWaiters > 0` and bypassing the `250 ms` quiet window only for those pools during `EnsureWarm`, requiring `slot.Tag = expectedTag` in `EnsureWarm`'s `waitForWarm` and failing fast if the file changes again mid-warmup so a stale in-flight build neither reports false success nor stalls for 60 s, preferring non-`desiredSpec` candidates when trimming, keeping all `tagOfSpec` file hashing outside `creationGate`, refreshing `slot.Tag` atomically under `creationGate` to `warm.Prelude` on replenishment so concurrent edits still hand off to queued claimants, and resolving/claiming named-session pools after acquiring `entry.Gate` so queued `--reset` turns never use an evicted pool). It re-hashes non-full, failed, and `WarmupWaiters > 0` retained pools outside `creationGate` (so fixing a broken prelude auto-recovers in the background), rechecks the `250 ms` quiet window after pool hashing, serializes file-prelude creation exclusively through `ProcessStateGate` (`activeRuns = 0 && activeFilePreludes = 0`; `TryEnterFilePrelude` on background refill; cold file-prelude claims release `creationGate` before `EnterFilePreludeBlocking`; `--pool-size 0` `warmup` probes and failed prelude creations in `claimSession`, `replenish`, and `EnsureWarm` release both `creationGate` and `ExitFilePrelude` before calling `releaseSession` / `enqueueCleanupAndDrainIfCapped`; restoring `daemonDirectory` + `daemonBaseline` before every file prelude and verifying live `Directory.GetCurrentDirectory()` in `Enter`), runs `prepareCleanupWork` (`clearScriptStatics` + `IDisposable.Dispose()`) outside `cleanupBackpressureGate` so a slow script `Dispose()` never blocks unrelated turns, and holds `cleanupBackpressureGate` across the `creationGate` drain when `pendingCleanups.Count >= 15` so `pendingCleanups.Count` never exceeds `16` while running two-phase quiet-gated `completeUnloadSweep` (`GC.Collect(2)` + `WaitForPendingFinalizers()`, re-checking `IsQuiet 500L` before the second `GC.Collect(2)` + `releasedGate`-locked `drainReleasedSessions ()`) outside both `ProcessStateGate` and `creationGate` (unless forced by the `16`-item cap or `Metrics`), disposes direct top-level reference `IDisposable` bindings and resets all non-`initonly` static reference and value-type fields (`RuntimeHelpers.GetUninitializedObject` / `null` in `clearScriptStatics`, never invoking custom struct parameterless constructors) so `IDisposable` handles nested inside `[<Struct>]` records/tuples/arrays finalize and unlock deterministically without traversing shared BCL value-type internals, routes background creation failures and expired named sessions onto that deferred cleanup path, publishes replenished sessions under `creationGate`, rechecks empty-pool claims after acquiring the gate, and binds creation failures to the exact evaluated `Tag` (`PreludeEvaluationFailure`). Stateless runs exit `ProcessStateGate` in an inner `finally` before `releaseSessionWith`/`releaseSession` runs in the outermost `finally` (covering `Enter` failures and completing before replying).
- Default sessions evaluate one combined interaction: the infrastructure prelude (`fsionFsiState`, `exit` shadowing) plus the built-in `module Fsion` (`cwd`, `path`, `env`, `envOr`, `readText`, `writeText`, `json`), keeping exactly one `FSI-ASSEMBLY` per default session. `--no-prelude` (`ExecuteRequest.NoPrelude`) evaluates only the infrastructure prelude. A user prelude is evaluated as an interaction from its own directory after the built-in module; FSI `EvalScript` bindings do not survive into later interactions.
- `src/fsiond/NugetCache.fs` extracts top-level `#r "nuget: ..."` lines with a string/comment-aware scanner, keys a JSON cache under `FSION_CACHE_DIR` (default `%LOCALAPPDATA%/fsion/nuget-cache`, `$XDG_CACHE_HOME/fsion/nuget-cache` elsewhere) by `(TFM, RID, normalized directives, nuget.config fingerprint)`, resolves misses through `FSharp.Compiler.DependencyManager.DependencyProvider`, and feeds hits as `#r`/`#I` lines with the directive lines blanked in place (line numbers preserved). A configured user prelude goes through the same path during session creation.
- Protocol version 4: `ExecuteRequest.PreludePath` + `NoPrelude`. Client flags `--prelude <path>` / `--no-prelude` are mutually exclusive; the daemon accepts `--prelude <path>`, `--no-prelude`, and `--builtin-prelude` (used by wedged-respawn replacement when `DesiredSpec = Spec.Builtin` so startup `FSION_PRELUDE` does not override a subsequent builtin selection) plus the `FSION_PRELUDE` fallback; `--no-daemon` and `daemon start|restart` both pass the resolved prelude, and the drain-and-respawn replacement re-passes it explicitly.
- Black-box coverage: `tests/Fsion.Tests/PreludeTests.fs` (built-in helpers plus `ColdClaims` unchanged, opt-out, user-prelude preload with a package plus live edit, flag/env/config precedence) and `tests/Fsion.Tests/NugetCacheTests.fs` (cross-daemon cached-directive speedup with the feed removed, the dependency manager cache purged and `NUGET_PACKAGES` empty; string/comment extraction). `TestInfra` sets `FSION_CONFIG_DIR` per context and provides `createTinyPackage` (local `dotnet pack` feed), `writeNugetConfig`, and `purgeDependencyManagerCache`.
- Known limit: native library probing on cache hits is registered as `#I` directories (the contract's stated mechanism); a package with native assets is code-reviewed but not black-box tested.

## Goal 0006 — Hot Path & Burst Resilience

- `src/fsion/Program.fs` and `src/Fsion.Protocol/{Prelude,Ipc}.fs` own the default client path and IPC. Preserve config precedence, raw redirected output, and isolated pipe routing when changing client startup.
- `src/fsiond/SessionHost.fs` publishes a replenished session before releasing `creationGate`; an empty-pool claimant checks again after acquiring it. Oneshot bypasses the replenisher and creates only its requested session. Background refill requires 250 ms quiet and no waiting claimant, except explicit warmup.
- FCS detachment is serialized by `creationGate`. Full, non-compacting collectible unload normally waits for 500 ms quiet and no waiting claimant; 16 pending sessions trigger the backlog path. `GetMetrics` is an explicit collection barrier.
- For latency changes, use the [Goal 0006 evidence](docs/evidence/0006-evidence.md) and the runnable benchmark rules above. Keep the default-config, diverse and zero-gap burst measurements separate from the logged phase probe.

## Goal 0007 — Protocol Coexistence, Endpoint Hardening & Fault Isolation

- Protocol version 5 (`src/Fsion.Protocol/Protocol.fs`): `defaultEndpointName ()` embeds TFM + `buildFingerprint` so `net10.0` / `net11.0` and upgraded binaries isolate cleanly. Control frames (`GetStatus`, `Shutdown`, `Status`, `ShuttingDown`, `Failure`) decode regardless of wire version so `daemon status`/`stop`/`restart` always work across skew.
- IPC trust boundary (`src/Fsion.Protocol/Ipc.fs`, `src/fsiond/Program.fs`): Windows named pipes enforce `PipeOptions.CurrentUserOnly`; POSIX sockets use `0700` per-uid dirs, `0600` sockets, `flock` ownership lockfiles, and `setsid()` session detachment.
- `ProcessStateGate` (`src/fsiond/SessionHost.fs`) uses fair FIFO turn ordering, honors disconnect cancellation and `--timeout`, and detects nested same-daemon conflicting-epoch calls via `FSION_ACTIVE_ENDPOINT` / `FSION_ACTIVE_RUN_ID`.
- `Server.fs` uses atomic `Interlocked`/`Volatile` counters and non-collateral wedged draining (releasing endpoint ownership immediately while letting healthy siblings finish up to 60 s before self-kill). Named sessions persist generation tombstones so restarted daemons report explicit session-lost errors until `--reset`.
- Memory hygiene: `fsiond.fsproj` sets `System.GC.ConserveMemory = 9`; idle quiet unloads compact LOH (`CompactOnce`), and Windows trims idle working set via `EmptyWorkingSet` after `FSION_TRIM_IDLE_MINUTES` (default 5 min, `0` disables).

## Goal 0005 — Cross-Platform Packaging, Benchmark Gate & Documentation

- `bench/data.json` defines rounds/warmup, `BENCH_DOMAIN`, the `typical` payload shape, the AC-07 thresholds, and one entry per runner (`fsion`, `dotnet-fsi`, `bun`, `node`, `python`). `bench/run-bench.py` renders fresh F#/TS/JS/Python source per round from a per-invocation salt plus the round index (nonce embedded in the payload and output; arithmetic constant embedded in the expression), runs all present runners interleaved with a per-round rotation, and records a round's timings only after every runner exited 0 with byte-identical stdout. Historical outputs: `docs/evidence/0005-benchmark-report.md` + `docs/evidence/0005-benchmark-results.json`; `--require-ac07` exits 1 on an AC-07 threshold failure; `--require-goal0006` exits 1 on any Goal 0006 threshold failure and requires `hello`, `typical`, `diverse`, at least 30 measured rounds, and `fsion`, `dotnet-fsi`, and `bun`.
- Goal 0005 isolated its `FSION_CONFIG_DIR`; the current harness unsets it, sets empty `XDG_CONFIG_HOME` on POSIX, and verifies via `SHGetKnownFolderPath(FOLDERID_RoamingAppData)` that no `Roaming\fsion\prelude.fsx` exists on Windows (matching `Environment.GetFolderPath` semantics) to exercise default config resolution. It removes `FSION_PRELUDE` and assigns a unique `FSION_PIPE`. Default binaries are the gate-published client and built daemon; set `FSION_BINARY` and `FSIOND_PATH` to both packaged executables to measure a bundle. Keep the repo-local `bench/.work/run-<salt>` carrier.

In `SessionHost.fs`, file-mode execution reads UTF-8 source directly and evaluates through `EvalInteraction(chunk, sourcePath)` using FCS's `FSharpSourceTokenizer` to split top-level `;;` interactions with exact line/column offset preservation and Windows `file.fsx(line,col): ` diagnostic-header normalization (avoiding `EvalScript`'s ~25–30 ms synthetic `#load` wrapper), `Settings` sets `ShowDeclarationValues/ShowIEnumerable/ShowProperties = false` (skipping reflection value-formatting per binding), `CompilerDirectory` skips redundant `#cd` interactions (invalidated on `#cd`/`#silentCd`/`#load`). Goal 0006 supersedes the earlier replenish timing.
- `.github/workflows/ci.yml` runs the gate then `eng/package.ps1 -Framework net10.0` on `windows-latest`, `macos-latest`, and `ubuntu-latest`, uploads the archive, and installs `10.0.x` + `11.0.x` SDKs (the net10.0 test host needs the .NET 10 runtime while the 11.0 SDK drives the build); Ubuntu additionally installs `clang` and `zlib1g-dev` for NativeAOT.
- Historical Goal 0005 used an unconditional Gen-0 sweep. See [Daemon Pool & Isolation Invariants](#daemon-pool--isolation-invariants) for handle release and [Goal 0006](#goal-0006--hot-path--burst-resilience) for idle unload.

The client gained `--pool-size <n>` (env `FSION_POOL_SIZE`, Historical Goal 0005 default `3`, updated to `DefaultPoolSize = 4` in Goal 0006), resolved like `--idle-ttl`/`--session-ttl` and passed to every spawn (auto-start, `daemon start|restart`, `--no-daemon`, drain-and-respawn). Black-box coverage: `IsolationTests` `--pool-size reaches the auto-started daemon and zero disables warm sessions`.
- Docs: root `README.md` is the operator/agent entry point (architecture, install/package, CLI/env tables verified against `Program.fs`, prelude/cache behavior, the measured benchmark table and the honest AC-07 outcome); this file owns the agent-facing invariants.
