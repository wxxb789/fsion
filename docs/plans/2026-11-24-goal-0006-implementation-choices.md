# Goal 0006 — Implementation Choices

Execute the [contract](../goals/archive/0006-hot-path-and-burst-resilience.md) under the [core design](../core-design.md) and [converged specification](../specs/2026-11-22-fsion-core-design.md). Follow merged Goal 0005 (`280cd94`): black-box process tests, a benchmark report with raw JSON, then evidence and closeout.

- Keep protocol v4. Retain two recent prelude specs (protecting any pool with active foreground or background `Claimers > 0` from eviction so an in-flight background creation always hands off to a queued claimant even if two other specs activate before or during the wait), each with a configurable watermark of four by default (`DefaultPoolSize = 4`), while `bench/run-bench.py` pre-warms its benchmark daemon with `--pool-size 12` to cover the 12-script zero-gap burst. (`DefaultPoolSize = 12` passed Windows and Ubuntu gates, but on `macos-latest` arm64 12 warm FCS sessions held ~514–547 MiB post-GC heap and exceeded Goal 0002's `< 400 MiB` bound in `IsolationTests`; `DefaultPoolSize = 4` keeps everyday memory ~60% lower and well below `< 400 MiB` across all three OSes.) Publish background creations before releasing the creation gate; after waiting on that gate a claimant checks the queue again. A oneshot daemon creates its sole session on demand and never replenishes. Compute file-prelude SHA-256 tags outside `poolGate` (so same-length/same-timestamp overwrites invalidate immediately without stale cache loops), and tag a newly compiled prelude by its actual input bytes.
- Reset cwd before responding (verifying the live OS `Directory.GetCurrentDirectory()` on epoch entry and restoring `daemonDirectory` in `ExitFilePrelude` so a prelude that calls `SetCurrentDirectory` cannot leak `cwd` into subsequent runs). On the NativeAOT `fsion` client, resolve explicit `FSION_CONFIG_DIR` paths locally via `Path.GetFullPath` (matching `warmup` byte for byte, including Windows cross-drive-relative paths) while leaving `PreludePath = None` when `FSION_CONFIG_DIR` is unset so `fsiond` resolves implicit user preludes from POSIX `XDG_CONFIG_HOME` / `HOME/.config` / startup-cached OS account home (`SpecialFolder.UserProfile` queried with `HOME` cleared, supporting NSS/SSSD/LDAP, plus macOS fallback to `~/Library/Application Support/fsion/prelude.fsx` when XDG has none) and startup-cached Windows `SpecialFolder.ApplicationData`, skipping per-invocation Win32 shell-folder lookups on the default unconfigured client hot path (`Ping(None, false)` resolves strictly to `Spec.Builtin`). Reuse the last request's environment map for matching snapshots and reconcile against a live snapshot before the next epoch without writing unchanged values. Serialize file-prelude session creation exclusively through `ProcessStateGate` (`activeRuns = 0 && activeFilePreludes = 0` so neither scripts nor subsequent file preludes can observe another prelude's `cwd` or environment mutations; `TryEnterFilePrelude` runs when idle; cold file-prelude claims release `creationGate` before `EnterFilePreludeBlocking`; `--pool-size 0` `warmup` probes release both gates before `releaseSession`; `replenish` re-verifies the `250 ms` quiet window after pool hashing and skips currently ineligible file pools so builtin/bare pools still warm); re-hash non-full and failed retained pools outside `creationGate` so fixing a broken prelude auto-recovers in the background, route background `createWarmSession` failures and expired named-session TTL evictions onto the deferred `500 ms` quiet cleanup path, bind prelude-creation failures to the exact evaluated `Tag` (`PreludeEvaluationFailure`), and fail `EnsureWarm` if the requested pool times out before filling. Track the compiler directory in FCS when available, and fall back to `#cd` otherwise.
- Exit `ProcessStateGate` in an inner `try ... finally` before running stateless `releaseSessionWith` / `releaseSession` in the outermost `finally` of `runInSession` (matching base `c14f60c` so user `IDisposable.Dispose()` cannot hold `ProcessStateGate` across epochs and stateless cleanup still runs even if `processState.Enter` or restoring `daemonDirectory` throws), while completing `releaseSessionWith` before replying to the caller. Run deferred `drainPendingCleanups` (`GC.WaitForPendingFinalizers()`) under `creationGate` outside `ProcessStateGate` after checking `processState.IsQuiet 500L` (matching base `c14f60c` so an unloaded finalizer waiting on a subsequent script turn can never deadlock `ProcessStateGate.Enter`). Always sweep finalizers on stateless release. Sample Gen-0 and Gen-1 counts before evaluation. Collect Gen-0 if neither count changed, Gen-1 if only Gen-0 changed, and Gen-2 if a Gen-1 or Gen-2 collection intervened. Recheck counts after ephemeral sweeps to cover racing promotion. Clear script statics and compiler async locals, then wait for pending finalizers before replying. Leave FCS detachment on the deferred path rather than acquiring `creationGate` on every release. After 250 ms of quiet and without claim waiters, allow background replenishment; explicit warmup can bypass the quiet requirement. During quiet replenishment request optimized, nonblocking Gen-1 collection before enqueueing, without relying on it for handle safety. Defer full unload until 500 ms of quiet with no waiting claimant, or until 16 sessions are pending. Metrics retains its explicit collection barrier, and `bench/run-bench.py` enforces `--timeout` on Windows pipe metrics reads via a daemon thread as well as POSIX sockets.
- Publish the framework-dependent daemon with ReadyToRun only in `eng/package.ps1`, which already supplies the host RID. Keep ordinary RID-less builds unchanged. The earlier six-round probe informs this choice, not a guaranteed speedup.
- Compare the original default-path campaign to unlogged runs of the exact Win-x64 package using the same repo-local carrier. Use a uniquely named isolated endpoint and the normal config lookup (`XDG_CONFIG_HOME` set to an empty directory on POSIX, and a clean Windows Roaming profile verified via `SHGetKnownFolderPath(FOLDERID_RoamingAppData)` without overriding `APPDATA`). Record the separate 12-sample logged phase breakdown, all 12 zero-gap samples, process metrics, and exact parity. Run build, full test gate, package smoke, and measurements serially. Preserve Goal 0005 artifacts and report every unmet threshold even if the harness exits 0.
- Do not redesign FCS isolation, cache user scripts, or expand into Goals 0007/0008.

## Contract Amendment Disclosure

The Carbon goal author / operator amended the active contract before moving it into `docs/goals/archive/` under GDD Phase 0 (`3fcc0a7`; never rewritten after archival). Additionally, after `macos-latest` arm64 CI showed 12 warm FCS sessions (`513.6–546.9 MiB`) exceeding Goal 0002's `< 400 MiB` post-GC heap bound, the owner approved setting production `DefaultPoolSize = 4` while `bench/run-bench.py` pre-warms its benchmark daemon with `--pool-size 12`. The [closeout evidence](../evidence/0006-evidence.md) records the gate exits, package provenance, and equal-pool (`--pool-size 12`) vs default-pool burst controls.

- **Handle unlock (scope and verification clauses 1–2):** Replace the proposed Solo No-Handle Fast Path and its unsound net OS handle-count skip with deterministic, generation-escalating sweeps and promotion of warm sessions by the replenisher before enqueue. Tighten the promoted-object control to open the stream in a helper (no top-level static), survive mid-run collections into Gen-1 or Gen-2, and require both immediate exclusive open and delete without retries. Replace the solo control with the Aggregate Handle-Drop Counterexample Control: independent closes can lower the net count even while a new stream leaks.
- **Default pool and burst:** The pre-archival amendment raised the warm pool (eight was the contract example) and measured the 12-script zero-gap burst against the warm pool rather than `--pool-size 3`, preserving `< 750 ms` max and `<= 1.25x` spaced `typical` while warm sessions cover the burst (and allowing single-session creation latency once drained). Owner decision during PR #6 closeout set production `DefaultPoolSize = 4` (keeping all three OSes under `< 400 MiB`) and had `bench/run-bench.py` pass `--pool-size 12` explicitly.
- **Burst-quiet background window:** Replace the generic idle unload rule with explicit quiet windows (`activeRuns = 0`) for both replenishment and full GC: about 250 ms before background creation and 500 ms before `drainPendingCleanups`, with a safety ceiling of 16 pending sessions.
- **Same-harness baseline and unseen `hello`:** Use the upgraded default-path `c14f60c` baseline (`hello` 65.4 vs 52.1 ms for `bun`; `typical` 84.9 vs 52.4 ms; `diverse` 75.6 vs 53.3 ms; burst 109.9 ms median and 2,366.2 ms max). Replace the masked-config 54.4 ms comparison and `<= 1.00x bun` bar with 65.4 ms and `<= 1.05x bun`; keep the within-3-ms alternative and `>= 50x` over `dotnet fsi`. The prior Round 2 run (`4224e3e4`) beat `bun` outright: 49.1 vs 51.4 ms (0.956x).
- **Unseen `typical` and `diverse`:** Replace the masked-config `typical` baseline of 71.8 ms and the `<= 58 ms` / `>= 45x` targets with material improvements over the measured default-path baselines (84.9 ms `typical`, 75.6 ms `diverse`) and `>= 40x` over `dotnet fsi` for both. When `typical` remains above `bun`, report the measured client/IPC, daemon gate/release and FCS compile/execute phases without weakening stdout parity.
